# 额外植物学 1.21.1：项目说明与进度

[English](OVERVIEW_en.md)

这是《额外植物学》（Extra Botany）的**非官方** NeoForge 1.21.1 移植。本文说明这个分支是什么、2.0.0 这一版做了什么、它和原版有哪些不同，以及哪些地方还没有验证。

- 逐条的修改记录：[PORT_AUDIT.md](PORT_AUDIT.md)
- 游戏内验收清单：[ACCEPTANCE.md](ACCEPTANCE.md)

**当前状态**：代码、数据和自动测试已经完成；游戏内的验收（画面、手感、多人、旧存档）还没有完成。

## 这是什么

《额外植物学》是植物魔法（Botania）的附属模组：新的花、遗物、饰品、盔甲套装和 Boss。

| 组件 | 版本 |
|---|---|
| Minecraft | 1.21.1 |
| NeoForge | 21.1.248 或更高的 21.1.x |
| Java | 21 |
| 植物魔法（Botania） | 456 |
| Patchouli | 1.21.1-93 或更高 |
| Curios | 9.5.1 或更高 |
| JEI、EMI、KubeJS | 可选 |

## 来源

| 版本 | 仓库 | 在本分支里的作用 |
|---|---|---|
| 原版 1.12.2 | `ExtraMeteorP/Extra-Botany`，`master`（`4ad2cc9`） | 行为和数值的基准（只有 1.12 才有的内容） |
| 原版 1.16.5 | `ExtraMeteorP/Extra-Botany`，分支 `1.16`（`f96f6d3`） | 行为和数值的基准（1.16 的内容，以及两个分支都有的内容） |
| 《额外植物学：重燃》1.20.1 | `Lounode/ExtraBotany`，`release-1.20.1-1.9.2`（`a4d4f2a`） | 工程的底座；重燃新增的内容保留 |
| SCEX 预览版 | `2.0-scex.1` 到 `2.0-scex.10-dev` | 最初的 1.21.1 移植，本版的起点 |
| 本版 | `2.0.0` | 第一个正式版本号 |

这一版的做法是**以原版的源码为准**：

- 原版有的内容，逐个类对照 1.12 和 1.16 的源码重写。
- 重燃新增、原版没有的内容（例如回音花、商友兰、伐木花、蕴魔瑾）保留原来的设计，只修问题。
- 注册 ID 和存档的键名不变，旧存档可以继续使用。

## 这一版做了什么

### 按原版恢复内容和行为

在起点版本里，原版的不少内容只有物品和贴图，功能没有实现，或者行为和数值与原版不同。这一版对照源码逐个重写：

- **伤害系统**：原版的穿透伤害和直接扣血以前是空实现，现在恢复了。
- **雷之律者**（征服宝石）：以前宝石没有任何效果。现在有能量、反击、心斩、能量条和玩家身上的装甲。
- **银翼护卫套装**：四个套装效果和每件的属性以前都没有实现。
- **坐骑**（机车、飞碟）：按原版的运动规则重写，补上了真理之钥、能量条和音效。
- **遗物**：焢煌之境：劫炎永燎、亚空之矛、犹大的誓约（包括"神圣制裁"效果）、王之花园、静籁永恒、限量补给袋、五把遗物剑。
- **机器和方块**：魔力缓存器、量子魔力缓存器、FE转换器、液态魔力转化器、活石桶、不随想之茧、星尘莲。
- **空之律者**（1.12 的 Boss）：按原版的节奏和规则重写，包括护盾、特殊攻击、矛枪的闪电链和支援者。
- **本我**（1.16 的 Boss）：是一个单独的 Boss，使用召唤者的名字和皮肤。阶段、攻击间隔、八种地雷阵型、仆从和属性都和原版逐项对照过。
- **通用符文**：元灵符文和大罪符文重新可以代替植物魔法的符文。
- **奖杯**和进度"雷区激活"：数据一直在，但是以前没有代码授予它们。

### 两个原版分支的内容放在一起

原版 1.12 和 1.16 的内容并不相同，本分支两边都有：

- 只在 1.12 里的：空之律者、星尘莲、王之花园、亚空之矛、犹大的誓约、不随想之茧、量子魔力缓存器、液态魔力转化器、限量补给袋、奖杯。
- 只在 1.16 里的：本我、机车和飞碟、焢煌之境：劫炎永燎、征服宝石、通用符文、彩虹花瓣。
- 盖亚守护者III（重燃对 1.12 那个 Boss 的移植）和本我（1.16）是两个不同的 Boss，可以分别召唤。

### 修掉的问题

审计记录里有编号的问题大约 190 条，每一条都写明了现象、原版的做法和处理方式。除了"和原版不同"的那些，还有：

- **功能缺陷**。例如：所有花的自定义数据都没有同步到客户端；五种花的迷之炖菜效果要重新进入世界才生效；盾牌的格挡效果在伤害没有被挡住时也触发；勇士盾的"解放"在 1.20.5 之后永远无法使用；白雏菊项链右键一次转化两次；四种材料的增益因为判断写反，60 tick 里有 59 tick 都在刷新并消耗魔力。
- **每 tick 的浪费**。例如：攀爬饰品每 tick 为世界里的每个生物查找饰品栏；每个祭坛每 5 秒尝试几百个起点来检查多方块结构；五种花每秒向客户端发一个完整的数据包；魔力条每一帧查找玩家身上全部的魔力物品。
- **遥测**。继承来的代码里有默认开启的遥测（bStats 和一个自定义的统计服务器）。这部分整个删除了：**本模组不向任何服务器发送数据**。

### 工程和数据

- 单模块的 NeoForge 工程，标准的 Gradle 布局。
- 客户端代码和通用代码分开：客户端包以外的类不引用客户端的类，发布 JAR 用脚本检查过。
- 数据生成器可以重新运行（以前在第三个生成器就崩溃），连续运行两次的输出完全相同；生成的文件和手写的文件分开存放。
- 使用 1.21.1 的机制：数据附加（玩家的能量和状态）、数据映射（茧的孵化表、燃料的燃烧时间）、标签、数据驱动的伤害类型和唱片。整合包可以用数据包调整这些内容。
- KubeJS 的配方支持在运行时验证过，写法见 [kubejs.md](kubejs.md)。
- 代码注释是中英对照的，写法见 [COMMENT_STYLE.md](COMMENT_STYLE.md)。

### 测试

游戏内自动测试（GameTest）从 88 个增加到 211 个，分在 40 个测试类里，全部通过。

### 性能

- 30 种花和机器各有一个测量场景：放 64 个同样的方块，测量服务端每 tick 的耗时。最贵的一种（鲜血妖姬）是每个方块每 tick 1 到 1.4 微秒，也就是 1000 个方块用掉一个 tick 的不到 3%。
- 唯一明显的热点是伐木花：64 朵花时，每朵每 tick 的开销从 5.3 微秒降到 0.7 微秒，最慢的 5% 的 tick 多用的时间从 7.2 毫秒降到 0.15 毫秒。
- 运行方法：`gradlew runGameTestServer -Pgametest_namespaces=extrabotany_perf`。
- 没有测量：客户端的渲染性能，以及 Boss 战里大量投射物同时存在时的开销。

### 图鉴和进度

- 恢复了 14 个图鉴条目，文字来自原版 1.12 的语言文件。
- 为以前没有条目的内容新写了 13 个条目（包括本我），文字按现在的功能编写。
- 恢复了原版 1.12 的 6 个进度，新增进度"击败本我"。

## 和原版的差异

原版是基准，但是这一版没有逐字照搬。差异分成下面几类；每一条的细节都在 [PORT_AUDIT.md](PORT_AUDIT.md) 各节的"和原版的差异"里。

### 平台带来的差异

- 目标是 1.21.1 / NeoForge / 植物魔法 456。物品数据用数据组件，玩家状态用数据附加，饰品用 Curios。
- 原版用 WAILA 和 The One Probe 显示机器的数值。这里用森林法杖的界面。
- 原版把元灵符文和大罪符文放进植物魔法的符文标签。植物魔法 1.21.1 的配方不再使用这些标签，所以这里用 mixin 实现同样的效果。代价是 JEI、EMI 和配方书不会把通用符文显示成可选的原料。

### 内容的组合方式

- 1.12、1.16 和重燃的内容并存。
- 自然蕴息宝珠（200,000 点自然之息）召唤本我，挑战券召唤盖亚守护者III。原版 1.12 里这两个物品都召唤盖亚守护者III，原版 1.16 里都召唤本我。
- 原版 1.16 的"进度要求"（九件遗物要求先击败本我）是一个**默认关闭**的配置项。原因是重燃改了其中几件遗物的获得方式，它们在击败 Boss 之前就能合成。
- 重燃给一部分物品换了名字和注册名，例如 `buddhistrelics` 现在是虚空万藏（`void_archives`），`treasurebox` 现在是潘多拉魔盒（`pandoras_box`）。

### 没有照搬的原版缺陷

审计的规则是：原版里明显的缺陷不移植，并且在记录里写明。例如：

- 强化斩击（薪炎之钥）在原版里从不造成伤害，因为构造方法没有保存主人。
- 真理之钥和犹大的誓约的光矛把主人保存在静态字段里，所有实例共用最后一个主人。
- 樱花的誓约直接修改全局的魔法伤害和熔岩伤害对象，让它们永久无视护甲。
- 静默贤者的套装判定引用了暗影武士的四件物品，所以套装永远凑不齐。
- 银翼射手"穿齐银翼护卫时不消耗魔力"只写在图鉴里，代码没有实现。这里按图鉴实现。
- 空之律者特殊攻击的预警消息因为一个判断写错而从未发出；二阶段抽到"虚空裁决"之后，直到三阶段都不再使用特殊攻击。
- 死亡戒指先扣魔力再检查间隔，所以每 tick 扣魔力却没有效果。
- 多人召唤的本我没有把生命值加满：两名玩家时它只有一半的生命值，第一个 tick 就进入地雷弹幕。
- 骑上机车的声音从不播放，因为服务端调用了只在客户端有效的方法。

### 多人游戏和服务端校验

- 原版有几处信任客户端发来的数据：心斩的位置和能量、坐骑的召唤和抓取、薪炎之钥的冲刺和终结技。这里都由服务端检查和计算。
- 技能造成的伤害把使用者记为攻击者，所以 PvP 规则和和平友好之证都生效。原版的几种伤害没有攻击者。
- 多处"每 tick 给玩家发一个数据包"改成客户端自己计算、服务端只在状态变化时同步。

### 不联网

- 原版在启动时从网上下载贡献者名单，并按名字从网上下载皮肤。这里把名单（45 个名字）写进代码；本我使用服务器玩家列表里召唤者的皮肤，本我仆从使用观看者自己的皮肤。

### Boss 的公共规则

- 空之律者和本我使用这个模组里盖亚守护者的公共规则：召唤时检查场地里每名玩家的物品栏和饰品栏；战斗中只收缴手持、穿戴和佩戴的违规物品。原版只检查召唤者，并且丢出物品栏里的全部违规物品。
- Boss 的攻击只伤害玩家。攻击的目标是最近的玩家；原版总是选玩家列表里的第一名。

### 数值和规则的调整

- 魔力缓存器的传输速度是 1000 点每 tick（原版 1.16 的值；1.12 的默认值是 400）。
- FE转换器和液态魔力转化器不会凭空丢失或者产生资源。
- 星尘莲没有"自然蕴息宝珠让花费减少 20%"的规则；刚被传送的生物 40 tick 内不会再被传送。
- 限量补给袋：玩家打开的第一个袋子一定给一个空的律者核心，因为制作空之律者核心需要它。奖池保存在世界的存档数据里。
- 本我有 20% 的几率掉落它的唱片。原版里这张唱片没有来源。
- 影刃空挥时只对怪物召唤小精灵；原版会攻击 8 格内的任意生物。

### 没有移植的内容

- 犹大的誓约当作装饰品附加在饰品上的功能。
- 空之律者的四个配置开关。
- 原版 1.12 在完成 6、12、18 个进度时赠送物品的规则，以及 1.12 的其余进度。
- 西行寺幽幽子的折扇的蝴蝶没有命中效果。这和原版相同：原版没有写完。

## 验证状态

**已经验证**：

- 211 个自动测试全部通过。
- 数据生成器重复运行没有变化。
- 发布 JAR 没有重复的文件，没有测试和数据生成的代码。
- 开发环境的客户端能启动到标题界面。

**还没有验证**：

- 游戏内的画面和手感（模型位置、动画、粒子、界面、Boss 战的节奏）。
- 用发布 JAR 启动真正的专用服务器。
- 真实的多人游戏。
- 用真实的旧存档进入游戏。
- 整合包环境，包括 JEI 和 EMI 里的配方显示。

也就是说：**逻辑有测试，表现还需要人来看**。

## 构建

```
./gradlew build
```

成品是 `build/libs/extrabotany-neoforge-1.21.1-2.0.0.jar`，客户端和服务端使用同一个文件。运行全部测试：`./gradlew runGameTestServer`。
